## What changed

Reward arithmetic is preflighted before a batch mutates state.

- XpPolicy: full selected online XP, zero unequipped background baseline, all offline characters use background rules, applicable external effect pathway capped at 50%. No effects equipped/free bonuses in the scene. Fractional XP is retained, not rounded up.
- Existing `IdleboundFoundation.unity` uses the enhanced development presentation through its original component GUID. Scene files, SampleScene, IdleboundTest, settings, package manifest/lockfile, and assembly definitions are unchanged.

## Explicit engineering policies and remaining blockers

1. Partial ticks survive selection changes and same-assignment retries, but are abandoned on changing/unassigning/swapping an assignment (S3 explicit abandonment rule). Invalid commands do not change assignments or partial ticks, though valid elapsed time is settled before the command is evaluated.
2. A completed cycle's XP eligibility uses the selected/background state and effects at completion. Mid-cycle pro-rata attribution is not specified in design and is **not** invented. Completion-time attribution is a disclosed development policy pending production approval. State changes always settle through their timestamp first.
3. `SettleTo` requires nondecreasing **absolute session ticks**. Callers must use the session command API for time-sensitive mutations. Repeated timestamps are no-ops. Offline calls cap each submitted away interval at base four hours and advance the cursor across ineligible excess; callers must submit one contiguous offline absence once. This is not a secured offline replay system. Gear extension to seven hours, multi-call away-session accounting, membership transitions, wall-clock verification, save/load, and anti-cheat remain unimplemented.
4. Only known milestone rows are supplied. Production curve load intentionally fails until all exact rows are provided. Default harness gathers resources but awards no XP because per-action XP is missing. No invented curve or production XP/action. The optional fixture is **100000 XP per completed cycle**, purely to exercise level gates rapidly. It retains known milestone thresholds, does not synthesize intermediate levels, and always displays **Lv ≥** (known floor). Conservative gates may keep truly eligible intermediate requirements locked until a known milestone is reached.
5. Three initial characters remain inherited development fixtures. Real account-XP slot unlocking and free slots 1/3/8 are not implemented or redefined. Membership, capacity/overflow, recipes, tools/passive speed, gem odds, economy, combat, persistence and Supabase are out of scope. Decimal XP and checked integer quantities are in-memory engineering choices, not a production save schema or claim of infinite numeric storage.
6. External effects must carry unique source IDs and applicable skill IDs (`*` for all skills). The additive adapter is configurable and capped; equipment acquisition, compatibility, stacking, actual cape/enchant grants and UI equipment controls are not implemented. Tests inject effects; the scene grants none.
7. The live harness settles a contiguous focus/pause absence once on return, using background XP rules and the four-hour base cap. Unity pause/focus callbacks and the realtime process clock still need Windows/mobile verification; they are not trusted timestamps. The explicit offline-step button tests reward eligibility. App termination does not preserve state or establish persisted offline simulation. Use Pause automatic time for exact repeatable manual steps; paused harness time intentionally does not advance, including during absence.
