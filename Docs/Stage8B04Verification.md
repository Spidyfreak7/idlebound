## Deterministic engineering policies requiring production review

- Bank counts represent unequipped stock. Equip deducts exactly one; replacement returns the old item atomically. Unequip preserves the item's instance ID in the bank; re-equip reuses that instance before minting another. New crafted/looted identical units receive identity when first equipped. These are in-memory identities only; no save or reconciliation format is claimed. Quantity/instance/stat overflow fails before equipment mutation.
- A two-handed mainhand returns an existing offhand atomically and prevents offhand equip until removed. This is a development compatibility rule, not an approved weapon taxonomy. Equipped products cannot be production ingredients yet: session construction rejects recipes requiring equipment IDs until instance-aware reservations exist.
- Damage is the development base plus flat gear damage bonuses, multiplied by the outgoing triangle. Incoming damage is `max(0, enemy damage × outgoing triangle − flat gear defense)` and is bounded by current HP. There are no crits, accuracy rolls, level-derived damage/HP or implicit minimum damage. Zero damage after armor is absorption, not a missed attack. HP does not change with XP/levels or equipping.
- Positive integer-tick clocks start with full attack intervals. On simultaneous events the player attacks first; a killed enemy cannot retaliate. A normal enemy immediately respawns at full HP with a full enemy interval; the player's next attack also waits its interval. No travel delay, corpse delay or immediate free attack. All these timing choices require final design approval.
- Equipping/unequipping during combat settles old gear first, resets only the player's attack interval, and preserves both HP values and the enemy clock. The equipped mainhand chooses the style; unarmed is Melee. A supplied mismatching style is rejected.
- Selecting another character settles old XP eligibility first and preserves combat state. Stopping/changing/swapping assignment discards that encounter's enemy HP and timers; character HP and prior XP/loot remain. Swapping displaces the former occupant rather than exchanging both assignments. One exact monster activity can have only one assigned character, regardless of combat style. Combat cannot coexist with production/gathering on the same character. Interrupted production refunds retain the existing live policy.
- XP is awarded on each actual hit to the weapon's corresponding skill using the existing eligibility policy at that event; no kill XP or future enchanting XP is added. All applicable background effects still cap at 50%; gear hooks grant none. Full-curve XP still saturates at 10M.
- Loot is granted only on defeat. Guaranteed drops consume no random roll; each probabilistic row has an independent keyed roll. Injected `IDeterministicLootRoller` implementations must be pure in seed/character/monster/persistent kill index/drop ID. The default counter-based hash is a development reproducibility tool, not secure server randomness. There is no pity, sale or save-backed replay protection.
- Settlement preflights combat HP, XP, loot, counters and bank operations alongside gathering/production. Repeated timestamps do nothing; rewinds fail; overflow, invalid random output or event-budget exhaustion commits nothing. The global 100000-event budget bounds work per settlement. On rejection, retry smaller chronological chunks from the unchanged settlement timestamp; do not repeatedly submit the same oversized interval. Very long online intervals/custom short timers may hit the guard. Ordinary four-hour offline replay with the three sample fighters fits the default budget.
- Existing offline cap remains four hours per contiguous submitted absence. Excess time is discarded while the cursor advances, so it cannot be reclaimed by repeating the timestamp. The UI groups focus/pause absence, but no trusted clock, save persistence, extension gear or production offline reconciliation is implemented. Partition equivalence applies within eligible time and a stable role/effect/gear history; splitting absences to circumvent the cap is not supported.
- Death retains gear/XP/bank, removes the combat assignment and prevents restart while HP 0. No recovery timer is inferred. Noncombat work is not HP-gated in this prototype. The explicit DEV HP tool is solely for repeated tests.

Outstanding design decisions: final item/monster stats and content, requirement skill mapping, combat XP coefficients, defense and HP formulas, attack ordering/restarts/respawn delay, two-handed compatibility, recovery/food, bank limits, durable gear identity, instance-aware crafting, saving/offline replay authority and synchronization.
