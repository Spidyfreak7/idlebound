# Repository workflow

- Use `develop` as the permanent working branch for all development, bug fixes, UI updates and improvements unless the user explicitly instructs otherwise.
- Commit directly to `develop`. Do not create stage-specific branches unless explicitly requested.
- Leave `main` untouched until a version has been tested and approved by the user.
- Preserve existing branches and uncommitted changes. Do not force-push or use destructive resets.
- See `README.md` for GitHub Desktop checkout instructions.
